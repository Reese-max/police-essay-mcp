## 本次最小修正

在共用review推理指令加上TASK_BOUNDARY_INSTRUCTION，使既有draft_answer、compress_answer及初始化instructions都取得同一組約束，沒有更動API、版面或評分功能：

1. 逐項列出硬性數量、資源與範圍，按可獨立實施的措施或功能計數，不能用大標題打包規避。
2. 改善須同時說明既有控制的作用與缺口，保留有限用途。
3. 保持題示動作、對象、強度與規模，不把提示、分類等改寫成更強或全面措施。
4. 技術紀錄的事件與帳號關聯不等於已辨認實際操作者。

tests/fixtures/essay-boundary-cases.json的四個案例為自製、失敗導向對照，使用不同題材與最多兩項限制，未硬編F題答案。knownBad是刻意寫出的反例，reviewExpectation供人工或獨立模型語義評閱，沒有新增關鍵字評分器。新的MCP回歸只檢查原題材料未遺失及契約可取得，不代表模型已遵守或負向問題已解決。
